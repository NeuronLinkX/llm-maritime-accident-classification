    STEP 2 · SBERT 유사도 정량화

    재결요약서 임베딩 유사도 정량화 결과

    STEP 1에서 추출한 -건의 사고 경위 문장을 5개 한국어 SBERT 모델로 임베딩하고, 문서 쌍 사이의 코사인 유사도를 계산해 모델별 성능을 비교했습니다. 아래 임베딩 공간 산점도는 KMST 원 카테고리 라벨과 무관하게 SBERT가 문장 의미만으로 문서를 얼마나 가깝게/멀게 배치하는지를 보여줍니다.
    baseline선행 연구(윤보리 외, 2023)는 KorSTS로 파인튜닝한 SBERT 모델 하나만 사용했습니다. 본 연구는 그 선택을 그대로 따르지 않고 5개 모델을 직접 벤치마크해 재검증했고, ko-sroberta-sts가 gap 기준 최고 성능으로 선행 연구의 방침과 일치함을 확인했습니다.

    모델별 벤치마크 비교

    같은 카테고리(intra) 다른 카테고리(inter)
    gap = intra 평균 − inter 평균. 값이 클수록 임베딩이 같은 사고 유형을 더 가깝게, 다른 유형을 더 멀게 배치한다는 뜻입니다. gap이 가장 큰 모델을 STEP 3 군집화 입력으로 채택했습니다.

    임베딩 공간 (t-SNE 2D 투영)

    채택 모델()의 768차원 임베딩을 t-SNE로 2D에 투영했습니다. 점 하나 = 문서 한 건. 원래 KMST 카테고리 라벨로 색칠했습니다 — 점을 올리면 문서명이 뜹니다. 카테고리 수가 많아 상위 7종 외에는 "기타"로 묶었습니다.

    실제 유사도 쌍 예시

    집계된 평균 뒤에 있는 원 자료 — 채택 모델 기준 가장 유사한 문서 쌍과 가장 안 닮은 문서 쌍입니다. 유사도 1.0000에 가까운 쌍은 서로 다른 파일로 등록되었지만 내용이 사실상 같은 재결서(중복 등록)인 경우가 많습니다.

    STEP 3 · K-Means 군집화

    사고 유형 군집화 및 군집별 주요 인자

    STEP 2에서 채택한 SBERT 임베딩을 K-Means로 군집화했습니다. 군집 개수(K)는 Elbow(WCSS)와 Silhouette 두 지표를 함께 계산해 자동으로 정했고, 각 군집은 Komoran 형태소 분석으로 뽑은 특징 키워드로 해석했습니다.
    baseline선행 연구는 Elbow Method만으로 K=10을 결정했습니다. 본 연구는 Elbow+Silhouette을 함께 사용해 자동으로 K=5를 채택했습니다. 군집 수 자체가 선행 연구와 다르므로, 이후 해석은 선행 연구의 10개 군집 결과와 직접 비교하기보다 독립적으로 검증해야 합니다.

    군집 개수(K) 자동 탐색

    K=2~30 구간을 탐색해 Elbow(군집 내 거리 제곱합이 급격히 꺾이는 지점)와 Silhouette(군집 응집도·분리도 평균)를 각각 계산했습니다. 두 지표가 가리키는 K가 다르면 정량적 단일 지표인 Silhouette을 우선 채택합니다.

    군집 산점도 (t-SNE 2D 투영)

    STEP2와 동일한 좌표에 이번엔 K-Means가 찾아낸 군집 번호로 색칠했습니다. 위 STEP2의 "원래 카테고리" 산점도와 비교해 보면, 정답 라벨 없이도 임베딩만으로 얼마나 비슷하게 묶이는지 가늠할 수 있습니다.

    군집별 주요 사고 인자

    워드클라우드와 칩은 "이 군집에서 유독 자주 나오는" 특징 키워드입니다(군집 내 비중 ÷ 전체 코퍼스 내 비중 — 모든 군집에 흔한 "출항/조업/해상" 같은 상투어는 제외됩니다).

    소결

    군집별 주요 사고 인자 결과를 STEP 4(LLM 구조화 레이블링)로 넘기기 전에 정리한 소결입니다.
    STEP 4 · LLM 구조화 레이블링 (실험적)

    군집 → 사고원인 분류 레이블링

    STEP 3의 군집을 사전 정의된 사고원인 체계로 구조화하는 단계입니다. 아직 검증 전 실험 단계라 두 경로를 나란히 검토합니다. 결과를 그대로 결론으로 쓰지 않습니다.
    baseline아직 확립된 baseline이 없습니다. 향후 사람이 직접 분류한 라벨(또는 선행 연구의 워드클라우드 기반 해석)과 대조해 LLM 제안의 정확도를 검증할 계획입니다. 지금 나오는 결과는 사람 검증 전 초안입니다.

    OpenAI 기반 군집 레이블링

    STEP 3 군집별 특징 키워드와 대표 문장 일부를 config/config.php에 등록된 OpenAI 키로 서버 사이드에서만 호출해, 사전 정의된 사고원인 대분류 후보 중 하나를 제안받습니다. 키는 브라우저로 내려오지 않습니다. 결과는 검증 전 초안이며 사람이 다시 확인해야 합니다.
    군집 5개에 각각 라벨을 붙였고, STEP 3에서 818건 전체가 이미 이 5개 군집 중 하나에 배정돼 있습니다. 그래서 문서 하나하나를 다시 LLM에 돌릴 필요 없이, 소속 군집의 라벨을 그대로 적용(조인)하면 818건 전부가 분류됩니다. 다만 특징이 약한 군집(소결 참고)은 여러 사고 유형이 섞여 있을 수 있어, 그 군집에 속한 문서는 개별 재검토를 권장합니다.
    CSV 다운로드

    로컬 LLM(DGX Spark) 기반 레이블링

    같은 작업을 외부 API 없이 DGX Spark에 올린 로컬 LLM(step_4_process/local_llm_server.py)으로 수행하는 경로입니다. 인터넷 연결이나 API 키 없이 돌릴 수 있어 민감한 데이터(재결요약서)가 외부로 나가지 않습니다. 서버가 켜져 있어야 하므로, 먼저 "작동 유무 확인"으로 응답하는지 본 뒤 레이블링을 실행하세요.
    OpenAI 경로와 같은 방식으로, STEP3에서 이미 배정된 군집 소속을 이용해 818건 전체에 라벨을 적용합니다.
    CSV 다운로드

    로컬 LLM 다중 모델 비교

    모델 카탈로그(local_llm_server.py의 MODEL_CATALOG)에 등록된 모든 모델을 한 번에 순서대로 돌려, 같은 프롬프트로 군집 라벨링을 시키고 결과를 나란히 비교합니다. 처음 부르는 모델은 다운로드·로드에 시간이 걸릴 수 있습니다(모델 하나당 최대 4분 대기).
